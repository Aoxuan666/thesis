## 1 部署环境概述

### 1.1 系统组成与部署拓扑

本系统由三部分组成，部署时需按依赖顺序进行：

```
[数据库 MySQL 8.x]  ←  [后端 RuoYi 服务 :8299]  ←  [Nginx :80/443]
                                                        │
                                              ┌─────────┴─────────┐
                                              ▼                   ▼
                                     [Web 管理后台 dist]   [Unity WebGL 产物 /unity/]
```

- 数据库保存机器人、栋舍、异常、监测点数据；
- 后端提供 `/open/**` 签名接口与 `/system/**` 管理接口，并内网直连机器人底盘；
- Nginx 托管 Vue 后台与 Unity WebGL 产物，并反向代理后端接口；
- Unity 与 Web 后台通过 iframe + postMessage 联动。

### 1.2 硬件要求

| 项 | 最低要求 | 推荐 |
|---|---|---|
| CPU | 2 核 | 4 核及以上 |
| 内存 | 4 GB | 8 GB 及以上 |
| 硬盘 | 20 GB 可用 | 50 GB 及以上（WebGL data 约 76 MB，数据库增长预留） |
| 网络 | 可访问公网；后端能内网直连机器人底盘（端口 1448） | 固定公网 IP + 带宽 ≥10 Mbps |

### 1.3 软件要求

| 类别 | 软件 / 运行时 | 版本 | 用途 |
|---|---|---|---|
| 操作系统 | Ubuntu Server | 22.04 LTS | 部署服务器 |
| 运行时 | JDK | 17（Spring Boot 3）| 后端 Java 服务 |
| 数据库 | MySQL | 8.x | 数据存储 |
| Web 服务器 | Nginx | ≥1.18 | 静态托管 + 反向代理 |
| Node.js | Node.js + npm | 16+ / 18+ | 前端构建 |
| 容器（可选） | Docker + Docker Compose | 20.10+ / 2.0+ | 容器化部署 |
| 浏览器 | Chrome / Edge | 较新版本 | 访问验证（需支持 WebAssembly） |

> Unity WebGL 产物为纯静态文件，不需要 Unity 运行时； Unity 编辑器 2021.3.44f1c1 仅在**构建阶段**需要（在开发机上，不在服务器上）。

## 2 准备工作与依赖安装

### 2.1 需要下载到本地的软件与配置

依归集要求 2.7，以下软件/安装包需下载到本地留档（详见 `1.3.7-支持文件/环境支撑软件清单.md`）：

| 软件 | 版本 | 用途 |
|---|---|---|
| JDK | 17 | 后端编译运行 |
| MySQL Server | 8.x | 数据库 |
| Nginx | ≥1.18 | Web 服务器 |
| Node.js | 18 LTS | 前端构建 |
| Navicat（可选） | 15+ | 数据库迁移/管理 |
| Redis（可选） | 6+ | 缓存（绑定关系、nonce 防重放） |
| Docker / Compose（可选） | 20.10+ / 2.0+ | 容器化 |

### 2.2 依赖安装

```bash
# Ubuntu 22.04
sudo apt update
sudo apt install -y openjdk-17-jdk mysql-server nginx
# Node.js 18（用 nodesource 或 nvm）
curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
sudo apt install -y nodejs
```

### 2.3 依赖管理文件

| 端 | 依赖文件 | 说明 |
|---|---|---|
| 后端 | `pom.xml` | Maven 精准版本号（RuoYi-Vue-Plus 5.x） |
| 前端 | `package.json` + `package-lock.json` | npm 锁版本 |
| Unity | `Packages/manifest.json` | Unity 包版本 |
| 本地联调 | 无（Python 标准库） | mock_server.py 无需第三方包 |

> 项目根目录中的 `*-api/*.java` 是**接口参考实现**，用于说明对接契约；实际可编译的后端工程与前端工程由团队 RuoYi 仓库提供，不在本归集包内。

### 2.4 环境变量与配置文件

需配置的关键文件：

| 文件 | 位置 | 作用 |
|---|---|---|
| `application.yml` | 后端 resources | 数据库连接、端口、Redis、签名开关 |
| `.env` | 前端根目录 | API 地址、Unity 资源地址 |
| `DatabaseQueryConfig.json` | Unity Assets/Resources | 数据库查询接口地址、租户、签名开关 |
| `RobotBackendConfig.json` | Unity Assets/Resources | 机器人控制接口地址、鉴权模式 |
| `MonitoringPointConfig.json` | Unity Assets/Resources | 监测点数据源、点位、阈值 |
| `WebBridgeConfig.json` | Unity Assets/Resources | WebBridge 目标域名、推送频率 |
| `nginx.conf` | web-integration/ | 静态托管、反向代理、MIME、CORS |

**配置模板**（`application.yml` 关键项）：

```yaml
server:
  port: 8299
spring:
  datasource:
    url: jdbc:mysql://<DB_HOST>:3306/poultry_twin?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: <DB_USER>
    password: <DB_PASSWORD>
  redis:
    host: <REDIS_HOST>
    port: 6379
# 开放接口签名
openapi:
  app-key: {APP_KEY}
  app-secret: {APP_SECRET}
  timestamp-tolerance-seconds: 300
  nonce-ttl-seconds: 300
```

> 密钥/账号密码按组下发，不写入代码仓库；`<...>` 为占位符，部署时替换。

## 3 部署步骤

### 3.1 多模块部署顺序

严格按以下顺序启动（存在依赖）：

```
1. MySQL 数据库（先建库、导入 schema.sql + data.sql）
2. Redis（若启用缓存/防重放）
3. 后端 RuoYi 服务（:8299）
4. 前端构建（npm run build:prod → dist）
5. Nginx（托管 dist + WebGL，反向代理后端）
```

### 3.2 数据库准备与恢复

```bash
# 建库
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS poultry_twin DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
# 建表 + 初始数据（归集包内已提供）
mysql -u root -p poultry_twin < 1.3.6-数据库/schema.sql
mysql -u root -p poultry_twin < 1.3.6-数据库/data.sql
# 若有生产 dump，改用 dump 恢复
mysql -u root -p poultry_twin < poultry_twin_dump.sql
```

用 Navicat 迁移见 `1.3.6-数据库/数据库设计说明.md` 第 6 节。

### 3.3 后端启动

```bash
# Jar 方式
java -jar ruoyi-admin.jar --spring.profiles.active=prod
# 或 Docker Compose（见第 4 节）
docker compose up -d
```

- 默认端口：**8299**
- 关键开放接口：`/open/robot/status`、`/open/inspection-exception/by-robot`、`/open/db/query`、`/open/monitor/points/latest`、`/open/robot/move|charge|stop`
- 后端需能内网直连机器人底盘 `http://{robot-ip}:1448/api/core/motion/v1/actions`

### 3.4 前端构建与部署

```bash
cd web-integration
npm install
npm run build:prod          # 产出 dist/
```

将 `dist/` 与 Unity 产物 `public/unity/` 一同放到 Nginx 静态目录：

```
/var/www/poultry-twin/
├── (Vue dist 内容) index.html, assets/ ...
└── unity/                 ← WebGL 产物
    ├── index.html
    └── Build/
        ├── unity.loader.js
        ├── unity.framework.js
        ├── unity.wasm
        └── unity.data
```

> 若构建工具产出文件名为 `PoultryTwin.*`（productName=PoultryTwin），以实际产物为准并同步修改宿主页引用。

### 3.5 Web 服务器配置（Nginx）

参考 `web-integration/nginx.conf`，关键配置：

```nginx
server {
    listen 80;
    server_name <your-domain>;

    # WebGL 静态资源
    location /unity/ {
        alias /var/www/poultry-twin/unity/;
        types { application/wasm wasm; }        # 关键: .wasm MIME
        add_header Cross-Origin-Opener-Policy same-origin;
        add_header Cross-Origin-Embedder-Policy require-corp;
    }

    # 反向代理后端
    location /prod-api/ {
        proxy_pass http://127.0.0.1:8299/;       # 注意尾斜杠剥离 /prod-api
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 前端 SPA
    location / {
        root /var/www/poultry-twin;
        try_files $uri $uri/ /index.html;
    }
}
```

配置校验与重载：

```bash
sudo nginx -t && sudo nginx -s reload
```

> 网关前缀 `/prod-api` 在签名时须剥离（见开发文档 6.1）。

### 3.6 Unity 侧配置（构建前）

在 Unity 编辑器中确认 `Assets/Resources/` 四个配置：

| 配置 | 关键项 | 生产值 |
|---|---|---|
| `WebBridgeConfig.json` | `targetOrigin` | **改成实际后台域名，禁止 `*`** |
| `RobotBackendConfig.json` | `baseUrl` / `authMode` | 后端地址 / OpenSign 或 BearerToken |
| `DatabaseQueryConfig.json` | `baseUrl` / `useSignature` | 后端地址 / 视网关是否验签 |
| `MonitoringPointConfig.json` | `dataSourceMode` / `sources` | Demo 改 Backend |

改完重新执行 `Tools → 数字孪生 → 一键构建 WebGL 到前端目录`。

## 4 容器化配置

若团队采用 Docker，项目提供`参考结构`（实际 Dockerfile 由团队工程提供）：

```yaml
# docker-compose.yml 参考
version: '3.8'
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: <PW>
      MYSQL_DATABASE: poultry_twin
    volumes:
      - ./1.3.6-数据库/schema.sql:/docker-entrypoint-initdb.d/1.sql
      - ./1.3.6-数据库/data.sql:/docker-entrypoint-initdb.d/2.sql
    ports: ["3306:3306"]

  backend:
    build: ./backend
    depends_on: [mysql]
    ports: ["8299:8299"]
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/poultry_twin

  nginx:
    image: nginx:1.25-alpine
    depends_on: [backend]
    ports: ["80:80", "443:443"]
    volumes:
      - ./web-integration/nginx.conf:/etc/nginx/conf.d/default.conf
      - ./dist:/var/www/poultry-twin
```

> 当前归集包中的 `Dockerfile` / `docker-compose.yml` 为**参考模板**，数据库初始化脚本已可直接挂载；后端镜像需由团队 RuoYi 工程构建。

## 5 部署验证

### 5.1 访问地址

```
http://<your-domain>/            → Web 管理后台
http://<your-domain>/unity/      → Unity 数字孪生场景（宿主页）
```

### 5.2 测试账户

> 归集要求 2.2.8 必须提供 1~2 个测试账户。以下为**占位模板，请由后端管理员按实际填入**：

| 角色 | 用户名 | 密码 | 可体验功能 |
|---|---|---|---|
| 管理员 | `admin` | `【由管理员下发】` | 用户管理、认证、全功能 |
| 普通用户 | `test_user` | `【由管理员下发】` | 查看大屏、切换机器人、查看异常与监测点 |

> 演示模式：Unity 侧 `setDemoMode{enabled:true}` 可在无真实数据时展示假数据，便于评审时无需后端即可看效果。

### 5.3 核心功能验证步骤

1. **静态资源**：浏览器 Network 检查 `/unity/Build/` 四个文件均 200，`.wasm` 返回 `application/wasm`；
2. **场景就绪**：Unity 控制台/页面收到 `ready` 事件（带 `actions` 数组）；
3. **后端接口**：`curl 'http://{host}:8299/open/robot/status?robotId=B{ROBOT_IMEI_C}'`（带签名头）返回 `code=200`；
4. **异常接入**：HUD 下拉选机器人 `{ROBOT_IMEI_A}`（栋舍 49），画面/列表出现 14 条异常标记；
5. **状态联动**：Web 后台点击「开始巡检」「全景」，Unity 响应且 `ack` 返回 `ok:true`；
6. **监测点**：四个点位卡片显示温湿度/CO₂/氨气，P04 超阈值时变红告警；
7. **导出**：点击「导出异常清单」浏览器下载 Excel。

## 6 部署注意事项

1. **签名头与时差**：后端与 Unity 服务器时间偏差需在 ±5 分钟内，否则 401；
2. **网关前缀**：`/prod-api` 只加在 URL，不参与签名；nginx 反代时需正确剥离；
3. **限流**：平台配额 120 次/分钟（同一 appKey），Unity 轮询已控制在约 80 次/分钟；部署多个实例时共享配额需重新核算；
4. **CORS**：WebGL 跨域请求需后端/网关返回 `Access-Control-Allow-Origin` 等头，并正确响应 OPTIONS 预检；
5. **混合内容**：https 页面不能请求 http 接口，须上 https 或同域反代；
6. **targetOrigin**：上线前从 `*` 改为实际域名；
7. **防火墙**：只开放 80/443；数据库 3306、后端管理端口不对外；后端需能访问机器人底盘内网端口 1448；
8. **权限**：WebGL 目录设只读；上传目录单独授权。

## 7 常见问题与故障排除

| 现象 | 原因 | 解决 |
|---|---|---|
| 端口被占用启动失败 | 8299/3306 被占 | `ss -lntp` 查占用，改配置停旧进程 |
| 后端起不来 | JDK 版本不符 / 配置缺失 | 确认 JDK 17；核对 application.yml |
| 数据库连接失败 | 账号密码/地址错误，3306 未开 | 核对凭据；本机 `mysql -h【host】` 测试 |
| 接口 401 签名错误 | 签名算法/密钥/时差不一致 | 用 `tools/check_inspection_api.py` 复算签名对比 |
| 接口 404 No endpoint | 路由未部署 | 确认后端已部署对应 Controller，nginx 前缀正确 |
| 接口 429 | 请求超频 | 降低轮询频率；检查是否多实例共享配额 |
| 页面一直转圈 | WebGL 四件套某个 404 | Network 查具体文件，核对路径与文件名 |
| `.wasm` MIME 错误 | Nginx 未配 wasm 类型 | 加 `types { application/wasm wasm; }` |
| 白屏 / CSP 错误 | 缺 `wasm-unsafe-eval` 或 COOP/COEP | 配 CSP 与响应头 |
| 按钮点了没反应 | WebBridge 未挂载 / 命令未就绪 | 查 Console `[WebBridge] 已自动挂载`；用 send() 返回值判断 |
| 导出 Excel 不下载 | iframe 缺下载权限 | 加 `allow="downloads"` 或 sandbox 令牌 |
| 切标签页回来位置跳变 | runInBackground 未开 | 构建工具检查项已包含，重新构建 |
| npm install 报错 | 网络/版本 | 用 `npm ci` 按 lock 文件安装 |
