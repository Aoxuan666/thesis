## 一、一句话定位

一套**面向鸡舍巡检机器人的数字孪生系统**：Unity 2021.3.44f1c1 构建 WebGL 包嵌入 Web 管理平台，按栋舍参数程序化生成笼架/笼位，实时接收机器人位姿与巡检异常（鸡只死亡、弱鸡、脏蛋等），在三维场景中标注异常位置并联动信息面板；数据来自 4 个 Java 开放接口，采用 HMAC-SHA256 七段签名鉴权与 `afterId` 增量拉取。

关键前提（容易理解反）：**巡检由云端下发指令后才开始，孪生端不发起巡检**，它只是在 `Play` 后自动接入、轮询当前轮次的结果。

| 项 | 值 |
|---|---|
| 客户端 | Unity 2021.3.44f1c1，WebGL（IL2CPP + Brotli），另有 Windows 独立版 |
| 代码规模 | 58 个 C# 脚本 / 27,386 行；3 个 `.jslib`；另含 Web 集成层 5 文件、后端 11 文件 |
| 数据层 | 4 个开放接口服务：巡检异常、固定监测点、机器人状态与运动、通用白名单查表 |
| 通信 | 前端 ↔ WebGL：`PoultryTwinBridge.jslib`，18 条命令 / 11 类事件；后端 ↔ Unity：HTTP + HMAC 签名 |
| 场景 | 主场景 `论文.unity`（4,539 个 GameObject、15 根根对象），HUD Canvas 1920×1080 |

## 四、文档里没写、但分析时一定会踩的 5 个事实

1. **字段类型与接口文档不符**。`exceptionPosX` / `exceptionPosY` / `exceptionJudgmentValue` 文档写 decimal，实测返回**字符串**；`exceptionColNo` 实测 14/14 全为 `null`、`exceptionRowNo` 为 `-2`。因为 `JsonUtility` 是强类型的，`int` 字段遇 `null` 会抛 `Invalid value` 并**整批丢数据**，所以代码里用字符串级 JSON 改写（`NormalizeRecordJson`）兜底。详见开发文档 6.3。
2. **坐标有两套基准**。场景侧 `TryConvertDisplayToInternal` 要求 `row>=1 && cage>=1`（display 是 1-based，内部是 0-based，必须 `+1`）；而异常自带的 `mapX/mapY` 实测恒为 (11.630, 5.800)，与 `RobotMapLocator` 标定范围（x 1.29~4.80、y -2~3.26）**不在同一坐标系**，不能直接兜底落位。
3. **限流是硬约束**。同一 appKey 全平台共用 120 次/分钟，超了直接 429。现取值：巡检 3 s、状态 1 s（合计 80 次/分钟），并带 `×2` 退避（上限 8/6 次）与成功后 `×0.5` 收回。
4. **接口返回是增量游标语义**。用 `afterId` 续拉，`truncated=true` 表示本页被 limit 截断需立刻续拉（上限 10 次）；云端清库后 `afterId` 必须归零，代码靠"本轮收到过数据 + 连续 2 次空响应"判定轮次切换。
5. **已核实但未完成的接口**：`/open/monitor/points/latest` 返回 `body.code=404`（后端未部署），且 Unity 侧 `FixedMonitoringPointApiClient` 尚未实现 HMAC 签名，真接会 401。这是已知缺口，不是 bug。

另：真实响应中 3 台机器人的栋舍分别对应 house 50/45/49，只有 house 49 有数据（14 条，`lastId=2917343`），另两栋为空是因为云端下指令后清空了该栋数据。
